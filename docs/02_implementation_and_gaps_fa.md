## A.۳ کد پایتون تست‌شده (تابع به تابع، با توضیح فارسی)

### تابع ۱: شبیه‌سازی یک مدل RMLM واقعی (برای تست الگوریتم‌ها روی داده‌ای که جواب درستش را از قبل می‌دانیم)

```python
import numpy as np

def simulate_rmlm(d, n, edge_density=0.35, alpha=2.0, seed=0):
    """
    یک DAG تصادفی می‌سازد و n مشاهده از مدل RMLM شبیه‌سازی می‌کند.
    قرارداد مقاله: گره‌ای با اندیس بزرگ‌تر می‌تواند والدِ گره با اندیس کوچک‌تر باشد
    (یعنی اندیس بزرگ = بالادست‌تر/نزدیک‌تر به منبع؛ این دقیقاً همان قرارداد
    "well-ordered DAG" در تعریف پایان بخش ۱ مقاله است).
    """
    rng = np.random.default_rng(seed)
    C = np.zeros((d, d))
    for i in range(d):
        for k in range(i+1, d):              # k والدِ بالقوه‌ی i است (اندیس بزرگ‌تر)
            if rng.random() < edge_density:
                C[i, k] = rng.uniform(0.3, 1.4)
        C[i, i] = rng.uniform(0.5, 1.3)       # وزن نویز خودِ گره

    # حل بازگشتی برای ساختن ماتریس ضرایب ماکس-خطی A از روی وزن یال‌های C
    # (این همان فرمول ۲ مقاله است: باید از سرچشمه‌ها به‌سمت پایین‌دست حرکت کنیم)
    A = np.zeros((d, d))
    for i in reversed(range(d)):              # اول منبع‌ها (اندیس بزرگ) پردازش می‌شوند
        A[i, i] = C[i, i]
        for k in range(i+1, d):
            if C[i, k] > 0:
                A[i, :] = np.maximum(A[i, :], C[i, k] * A[k, :])
        A[i, i] = max(A[i, i], C[i, i])

    # استانداردسازی هر سطر به نُرم ۱ — دقیقاً همان لم ۱(i) مقاله (فقط چون α=2 معتبر است)
    A = A / np.linalg.norm(A, axis=1, keepdims=True)

    # نویزهای فرشه‌ی استاندارد (مثال ۲ مقاله): P(Z<=z) = exp(-z^-alpha)
    U = rng.random((n, d))
    Z = (-np.log(U)) ** (-1.0/alpha)

    # فرمول (۲): X_i = max_j( a_ij * Z_j )   —  حل صریحِ مدل
    X = np.zeros((n, d))
    for i in range(d):
        X[:, i] = np.max(A[i, :][None, :] * Z, axis=1)

    return X, A, C
```

### تابع ۲: تخمین‌گر تجربیِ مقیاس σ̂² (پیاده‌سازی فرمول ۲۸ و ۳۰)

```python
def scaling(Mvals, R, k, dim_const):
    """
    تخمین‌گر تجربیِ σ̂² برای هر تصویر-بیشینه (max-projection):
        σ̂²  =  (dim_const/k) * Σ_{بزرگ‌ترین k مشاهده بر اساس R}  (Mvals/R)^2
    Mvals: بردار n-تایی مقدار تصویر-بیشینه (مثلاً M_ij = max(X_i, X_j))
    R:     شعاع کل بردار X برای همان n مشاهده  (‖X‖ اقلیدسی)
    k:     تعداد مشاهدات حدی (exceedances) که نگه می‌داریم
    dim_const: همان «d» فرمول ۳۰ مقاله — بُعد کلی مدل
    """
    idx = np.argsort(-R)[:k]          # اندیس k مشاهده با بزرگ‌ترین شعاع
    return dim_const * np.mean((Mvals[idx] / R[idx]) ** 2)
```

> ⚠️ **نکته‌ی مهم دیباگی که خودم گرفتار شدم و شما نباید بشوید:** فرمول (۳۰) می‌گوید `(d/k) * Σ`. اگر به‌جای `Σ` (مجموع) از `np.mean` استفاده کنید *و* هم‌زمان ضریب `d/k` را هم نگه دارید، عملاً یک‌بار اضافی روی k تقسیم کرده‌اید (چون `np.mean` خودش تقسیم بر k را انجام می‌دهد). این دقیقاً باگی بود که باعث شد اولین نسخه‌ی من همه‌ی σ² ها را نزدیک صفر تخمین بزند به‌جای ۱. فرمول درست: `dim_const * np.mean(...)`.

### تابع ۳: ساخت تصویر-بیشینه (max-projection)

```python
def build_M(X, cols, weight=1.0):
    """بیشینه‌ی چند ستون (گره) از X، با امکان ضرب در ضریب بزرگ‌نمایی a"""
    if len(cols) == 0:
        return None
    return weight * X[:, cols].max(axis=1)

def combine(*parts):
    """max گرفتن از چند بردار هم‌زمان (برای ترکیب M_i، M_j، M_O و ...)"""
    parts = [p for p in parts if p is not None]
    out = parts[0]
    for p in parts[1:]:
        out = np.maximum(out, p)
    return out
```

### تابع ۴: الگوریتم ۱ — تخمین ترتیب علّی (پیاده‌سازی قضیه‌ی ۵ و الگوریتم ۱ مقاله)

```python
def algorithm1(X, a=1.3, eps=0.15, k=250):
    """
    خروجی: لیستی از گروه‌ها. گروهِ اول = گره‌های منبع (source) که اول پیدا می‌شوند،
    گروه آخر = گره‌هایی که آخر همه پیدا می‌شوند (پایین‌دست‌ترین/sink ترین).
    """
    n, d = X.shape
    R = np.linalg.norm(X, axis=1)
    remaining = list(range(d))
    order_groups = []
    O = []                                     # گره‌های قبلاً پیدا شده
    while remaining:
        if len(remaining) == 1:                # حالت پایه: فقط یک گره مانده
            order_groups.append(list(remaining))
            break
        col_min = {}
        for j in remaining:
            best = np.inf
            for i in remaining:
                if i == j:
                    continue
                # فرمول (۱۷) مقاله: (Δ_O)_ij
                Mij_O = combine(build_M(X, [i]), build_M(X, [j]), build_M(X, O))
                MiajO = combine(build_M(X, [i]), build_M(X, [j], a), build_M(X, O, a))
                MjO   = combine(build_M(X, [j]), build_M(X, O))
                s1 = scaling(MiajO, R, k, d)
                s2 = scaling(Mij_O, R, k, d)
                s3 = scaling(MjO,  R, k, d)
                delta = s1 - s2 - (a**2 - 1) * s3
                best = min(best, delta)         # همان colmin روی سطرها (فرمول ۱۷-۱۸)
            col_min[j] = best
        best_val = max(col_min.values())
        thresh = eps * abs(best_val) if best_val != 0 else eps
        chosen = [j for j in remaining if col_min[j] >= best_val - thresh]
        order_groups.append(sorted(chosen))
        O = O + chosen
        remaining = [j for j in remaining if j not in chosen]
    return order_groups
```

### تابع ۵: الگوریتم ۲ — تخمین ماتریس A (پیاده‌سازی گزاره‌ی ۲ مقاله)

```python
def algorithm2(X, order_groups, k):
    n, d = X.shape
    R = np.linalg.norm(X, axis=1)
    # اندیس جدید: گروهی که اول پیدا شده (منبع‌ها) → بزرگ‌ترین اندیسِ سبکِ مقاله می‌گیرد
    flat_new_to_old = []
    for g in reversed(order_groups):
        flat_new_to_old.extend(g)
    Xp = X[:, flat_new_to_old]
    dp = Xp.shape[1]
    A2 = np.zeros((dp, dp))
    for i in range(dp - 1):
        cols_i_to_end  = list(range(i, dp))
        cols_ip1_to_end = list(range(i+1, dp))
        s_i   = scaling(build_M(Xp, cols_i_to_end),  R, k, d)
        s_ip1 = scaling(build_M(Xp, cols_ip1_to_end), R, k, d) if cols_ip1_to_end else 0.0
        A2[i, i] = max(s_i - s_ip1, 0)                       # فرمول (۱۹)
        running = A2[i, i]
        for j in range(i+1, dp - 1):
            cols_j1_end = list(range(j+1, dp))
            s_a = scaling(build_M(Xp, [i] + cols_j1_end), R, k, d)
            s_b = scaling(build_M(Xp, cols_j1_end),        R, k, d) if cols_j1_end else 0.0
            val = s_a - s_b - running                        # فرمول (۲۰)
            A2[i, j] = max(val, 0)
            running += A2[i, j]
        A2[i, dp-1] = max(1.0 - running, 0)                  # فرمول (۲۱)
    A2[dp-1, dp-1] = 1.0
    A_est = np.sqrt(A2)
    # بازگرداندن به ترتیب اندیس اصلی
    A_full = np.zeros((d, d))
    for newi, oldi in enumerate(flat_new_to_old):
        for newj, oldj in enumerate(flat_new_to_old):
            A_full[oldi, oldj] = A_est[newi, newj]
    return A_full, flat_new_to_old
```

## A.۵ نکته‌ی مهم و صادقانه درباره‌ی یک انتخاب طراحی در تخمین‌گر

مقاله در بخش ۶ می‌گوید: «برای تخمین σ̂²_{Mij} از نمایش زاویه‌ایِ *خودِ بردار (Xi,Xj)* استفاده می‌کنیم، نه بردار کامل X». یعنی به‌طور دقیق باید برای هر تصویر-بیشینه، **شعاع و آستانه‌ی مخصوص به همان زیرمجموعه** را حساب کرد (نه یک R و یک k مشترک برای کل مدل).

**من در این پیاده‌سازی یک انتخاب ساده‌تر ولی داخلاً سازگار کردم:** همیشه از شعاعِ کلِ بردار X (تمام ۳۰ یا d بُعد) و همان مجموعه‌ی k مشاهده‌ی حدیِ ثابت استفاده کردم — دقیقاً مثل فرمول (۳۰) خودِ مقاله برای تک‌گره‌ها، فقط تعمیم‌یافته به همه‌ی max-projection ها. این یک تخمین‌گر معتبر و منسجم است (و در تست بالا هم خوب کار کرد)، ولی **دقیقاً منطبق بر جزئیات فنیِ ریزِ روشِ اصلیِ مقاله (که به مقاله‌های Krali 2025 و Klüppelberg & Krali 2021 ارجاع می‌دهد) نیست.**

این خودش را دقیقاً به یک **شکاف پژوهشیِ واقعی** تبدیل می‌کند — به آن در بخش B (شکاف شماره ۱۰) برمی‌گردیم.

def to_frechet(X, alpha=2.0):
    n, d = X.shape
    U = np.zeros_like(X)
    for i in range(d):
        ranks = X[:, i].argsort().argsort() + 1     # رتبه‌ی هر مشاهده
        U[:, i] = ranks / (n + 1)
    return (-np.log(U)) ** (-1.0/alpha)

### گام ۴ — آستانه‌گذاری سخت (بخش ۷.۱ مقاله)

```python
def hard_threshold_dag(A, delta):
    """
    یال j→i را نگه می‌دارد اگر:
    A[i,j] > max_k( A[i,k]*A[k,j]/A[k,k] ) + delta
    """
    d = A.shape[0]
    edges = []
    for i in range(d):
        for j in range(d):
            if i == j or A[i, j] <= 0:
                continue
            best_indirect = 0.0
            for kk in range(d):
                if kk != i and kk != j and A[i, kk] > 0 and A[kk, j] > 0 and A[kk, kk] > 0:
                    best_indirect = max(best_indirect, A[i, kk]*A[kk, j]/A[kk, kk])
            if A[i, j] > best_indirect + delta:
                edges.append((j, i))     # یال از j به i
    return edges
```

### گام ۵ — انتخاب k و δ با nSHD (بخش ۷.۱، فرمول ۳۲)

```python
def shd(edges1, edges2):
    s1, s2 = set(edges1), set(edges2)
    return len(s1 - s2) + len(s2 - s1)          # ساده‌شده (بدون احتساب معکوس‌سازی جدا)

def nshd(edges1, edges2):
    denom = len(edges1) + len(edges2)
    return shd(edges1, edges2) / denom if denom > 0 else 0.0

def centroid_graph(Xf, k_values, delta):
    graphs = []
    for k in k_values:
        groups = algorithm1(Xf, a=1.3, eps=0.1, k=k)
        A_est, _ = algorithm2(Xf, groups, k=k)
        graphs.append(hard_threshold_dag(A_est, delta))
    scores = []
    for i, g in enumerate(graphs):
        total = sum(nshd(g, graphs[j]) for j in range(len(graphs)) if j != i)
        scores.append(total)
    best = int(np.argmin(scores))
    return graphs[best], k_values[best]

# مثل مقاله: برای هر k پایه در {50,60,70,80,90}، پنج مقدار نزدیک را امتحان کنید
best_graph, best_k = centroid_graph(Xf, k_values=[90, 92, 94, 96, 98], delta=0.1)
```

## B.۲ فهرست ۱۴ شکاف پژوهشیِ مشخص (هرکدام: شکاف → چرا مهم است → سوال پژوهشی → روش پیشنهادی)

### شکاف ۱ — فرض «کافی‌بودن علّی» (Causal Sufficiency) یعنی نبود متغیر پنهان مشترک

**شکاف:** مقاله صراحتاً می‌گوید (بخش ۲، بعد از قضیه‌ی ۱): «فرض می‌کنیم ساختار گرافی، کافی‌بودن علّی دارد» — یعنی هیچ عامل پنهانِ مشترکی وجود ندارد که هم‌زمان روی چند صنعت اثر بگذارد (مثل یک شوک ماکرواقتصادی جهانی که هم‌زمان روی نفت و خودروسازی اثر می‌گذارد، بدون این‌که نفت علتِ خودروسازی باشد).
**چرا مهم است:** در اقتصاد واقعی، متغیرهای پنهان (نرخ بهره، تورم، سیاست پولی فدرال رزرو) دقیقاً همین نقش را بازی می‌کنند. اگر این فرض نقض شود، گرافِ تخمینی می‌تواند یال‌های کاذب (spurious edges) نشان دهد.
**سوال پژوهشی:** «اگر یک عامل پنهانِ مشترک (مثل نرخ بهره) به‌طور مصنوعی به شبیه‌سازی اضافه شود، الگوریتم ۱ چقدر گراف اشتباه تخمین می‌زند، و آیا می‌توان با نگاه به مقاله‌ی Krali et al. (2023) درباره‌ی گره‌های پنهان، این مدل را تعمیم داد؟»
**روش پیشنهادی:** شبیه‌سازیِ مونت‌کارلو: یک گره‌ی پنهان اضافه کنید که والدِ چند گره‌ی مشاهده‌شده باشد، آن را از داده حذف کنید، الگوریتم را اجرا کنید و ببینید چند یال کاذب ظاهر می‌شود؛ سپس با روش‌های بخش «گره‌های پنهان» Krali et al. (2023) مقایسه کنید. (سطح دشواری: متوسط — قابل انجام با شبیه‌سازی)

### شکاف ۲ — انتخاب پارامترهای a و ε در الگوریتم ۱ به‌صورت اقتضایی (Ad Hoc)

**شکاف:** مقدارهای a=1.3 و ε=0.1 «شبیه به مقاله‌ی Krali (2025) برای رودخانه‌ها» انتخاب شده‌اند — یعنی هیچ قاعده‌ی خودکار یا نظری برای انتخاب این دو پارامتر روی این داده‌ی خاص وجود ندارد.
**سوال پژوهشی:** «آیا می‌توان یک روش خودکار (مثل یک نسخه‌ی bootstrap یا cross-validation در فضای مقادیر حدی) برای انتخاب بهینه‌ی a و ε طراحی کرد که خودش را با ثباتِ ترتیب علّیِ خروجی تنظیم کند؟»
**روش پیشنهادی:** یک تحلیل حساسیت سیستماتیک (grid search روی a∈[1.1,2] و ε∈[0.01,0.3]) روی داده‌ی شبیه‌سازی‌شده با ground truth مشخص انجام دهید و نمودار «دقت بازیابی ترتیب علّی» در برابر (a,ε) رسم کنید — این می‌تواند حتی یک نتیجه‌ی نظری (کراندار کردن خطا برحسب a) به همراه داشته باشد. (سطح دشواری: آسان تا متوسط — خوب برای شروع)

### شکاف ۳ — انتخاب k (تعداد مشاهدات حدی) هنوز کاملاً تجربی و اکتشافی است

**شکاف:** انتخاب نهایی k=۹۲ فقط از میان چند مقدار محدود (۵۰ تا ۹۰) و با معیار nSHD به‌دست آمده — این یک روش heuristic (اکتشافی) است، نه یک روش رسمیِ انتخاب آستانه (مثل روش‌های استاندارد نظریه مقادیر حدی، مثلاً نمودار هیل یا bootstrap دوگانه‌ی Hall/Danielsson).
**سوال پژوهشی:** «آیا روش‌های استاندارد انتخاب آستانه در EVT تک‌متغیره (مثل double-bootstrap برای شاخص هیل) را می‌توان به این محیط چندمتغیره/گرافی تعمیم داد و عملکردشان را با روش nSHD-centroid مقاله مقایسه کرد؟»
**روش پیشنهادی:** پیاده‌سازی روش double-bootstrap (Danielsson et al., 2001) در حالت چندمتغیره و مقایسه‌ی خروجی با آنچه در بخش ۷.۱ مقاله به‌دست آمده، روی همان دیتاست. (سطح دشواری: متوسط تا سخت)

### شکاف ۴ — نبود فاصله‌اطمینان/عدم‌قطعیت روی خودِ یال‌های گراف نهایی

**شکاف:** با این‌که قضیه‌ی ۱۲ مقاله یک نتیجه‌ی نظری کامل درباره‌ی نرمال‌بودن مجانبیِ Â می‌دهد (با فرمول دقیق ماتریس کوواریانس!)، در بخش کاربردیِ مالی (بخش ۷) **این نتیجه اصلاً استفاده نمی‌شود** — گراف نهایی فقط یک تخمین نقطه‌ای است، بدون فاصله‌اطمینان روی هیچ یال.
**سوال پژوهشی:** «با استفاده از فرمول کوواریانسِ قضیه‌ی ۱۲ (یا با bootstrap)، می‌توان برای هر یال گراف نهایی یک سطح اطمینان یا p-value محاسبه کرد؟ کدام یال‌ها از نظر آماری معنادارند و کدام‌ها فقط نویز آماری‌اند؟»
**روش پیشنهادی:** پیاده‌سازیِ bootstrap (نمونه‌گیری مجدد با جایگذاری از ردیف‌های داده‌ی اصلی، تکرار کل پایپ‌لاین صدها بار) و محاسبه‌ی «درصد ظاهرشدنِ» هر یال در نمونه‌های bootstrap — این دقیقاً همان کاری است که مفهوم «stability score» در پیوست D مقاله انجام می‌دهد ولی نویسندگان آن را رسماً به‌عنوان یک آزمون آماری (فاصله‌اطمینان) فرمول‌بندی نکرده‌اند؛ شما می‌توانید این کار را رسمی کنید. (سطح دشواری: متوسط — خیلی خوب برای یک مقاله‌ی مستقل)

### شکاف ۵ — نبود مقایسه با روش‌های رقیب روی همین داده

**شکاف:** مقاله اصلاً روش خودش را با رقیبان مستقیم مثل مدل‌های گرافی غیرجهت‌دارِ Engelke & Hitz (2020) یا روش درخت پوشای Tran et al. (2024) روی **همین داده‌ی ۳۰ صنعت** مقایسه نمی‌کند — فقط اشاره می‌کند که این داده قبلاً با PCA (Cooley & Thibaud, 2019) و خوشه‌بندی (Janßen & Wan, 2020) تحلیل شده، بدون مقایسه‌ی مستقیمِ گراف‌ها.
**سوال پژوهشی:** «اگر همین داده را با روش درخت پوشای Tran et al. (2024) یا مدل گرافی غیرجهت‌دار Engelke-Hitz تحلیل کنیم، چقدر ساختار پیدا‌شده با گراف این مقاله هم‌پوشانی دارد؟ کدام یک تفسیر اقتصادیِ قانع‌کننده‌تری می‌دهد؟»
**روش پیشنهادی:** پیاده‌سازی (یا استفاده از پکیج‌های R موجود برای) روش درخت پوشا و graphical extremes، اجرا روی همان بازه‌ی زمانی، و مقایسه‌ی nSHD بین سه گراف. (سطح دشواری: متوسط تا سخت، نیازمند تسلط بر چند روش)

### شکاف ۶ — فرض ایستایی (Stationarity) در بازه‌ی زمانی، بدون آزمون رسمی برای شکست ساختاری

**شکاف:** مقاله می‌گوید بازه‌ی ۱۹۸۹-۱۹۹۸ را «چون تقریباً ایستاست» انتخاب کرده — اما هیچ آزمون آماری رسمی (مثل آزمون شکست ساختاری Chow، یا آزمون CUSUM) برای اثبات این ادعا ارائه نمی‌دهد. مهم‌تر از آن: مدل کاملاً **ایستا فرض می‌شود** (گراف علّی هرگز در طول زمان تغییر نمی‌کند)، در حالی‌که در واقعیت، ساختار علّیِ اقتصاد می‌تواند در بحران‌ها عوض شود (مثلاً در بحران ۲۰۰۸، «مالی» احتمالاً از معلول به علتِ اصلی تبدیل شد).
**سوال پژوهشی:** «آیا گراف علّیِ تخمینی با یک پنجره‌ی زمانیِ غلتان (rolling window) در طول زمان ثابت می‌ماند؟ آیا می‌توان یک نسخه‌ی «پویا/زمان‌متغیر» از این مدل ساخت که تغییرات ساختاری را ردیابی کند؟»
**روش پیشنهادی:** اجرای کل پایپ‌لاین روی چند پنجره‌ی زمانیِ متحرک (مثلاً هر ۳ سال، با هم‌پوشانی) و رسم نمودار «چگونگی تغییر یال‌ها در طول زمان» — این می‌تواند یک مقاله‌ی مستقل کامل باشد. (سطح دشواری: متوسط، بسیار جذاب برای انتشار)

### شکاف ۷ — نقض فرض i.i.d. توسط خوشه‌بندی نوسان (Volatility Clustering / GARCH effects)

**شکاف:** کل چارچوب نظری (رگرسیونِ منظم، مقیاس‌ها) بر پایه‌ی این فرض بنا شده که مشاهدات X₁,...,Xₙ **مستقل و هم‌توزیع (i.i.d.)** هستند. اما بازده‌های مالی روزانه معروف است که **خوشه‌بندی نوسان** دارند (یک روز پرنوسان، روز بعد هم احتمالاً پرنوسان است) — یعنی وابستگی سریالی در دم توزیع وجود دارد که این مدل نادیده می‌گیرد.
**سوال پژوهشی:** «اگر داده را اول با یک مدل GARCH چندمتغیره فیلتر کنیم (باقی‌مانده‌ها/residuals را بگیریم) و بعد RMLM را روی باقی‌مانده‌ها اجرا کنیم، گراف علّی چقدر تغییر می‌کند؟»
**روش پیشنهادی:** برازش یک DCC-GARCH روی هر سری، استخراج residualها، تکرار کل تحلیل روی residualها و مقایسه با گراف اصلی (که روی بازده‌ی خام حساب شده). (سطح دشواری: متوسط تا سخت)

### شکاف ۸ — عدم وجود اعتبارسنجیِ پیش‌بینی‌کننده (Predictive / Out-of-sample Validation)

**شکاف:** هیچ‌جای مقاله بررسی نمی‌شود که آیا گراف تخمینی روی داده‌ی ۱۹۸۹-۱۹۹۸ واقعاً می‌تواند سرایت ریسک را در یک بازه‌ی زمانیِ **بعدی** (مثلاً بحران ۲۰۰۷-۲۰۰۹ یا کووید-۱۹) درست پیش‌بینی کند یا نه — یعنی گراف فقط توصیفی/درون‌نمونه‌ای (in-sample) است، نه پیش‌بینانه.
**سوال پژوهشی:** «اگر گراف را روی داده‌ی ۱۹۸۹-۱۹۹۸ تخمین بزنیم، آیا این گراف می‌تواند الگوی سرایت ریسک در بحران ۲۰۰۸ یا سقوط کووید-۱۹ (که اصلاً در داده‌ی آموزشی نبوده) را به‌درستی پیش‌بینی کند؟»
**روش پیشنهادی:** گراف را روی بازه‌ی آموزشی نگه دارید ثابت؛ روی داده‌ی ۲۰۰۷-۲۰۰۹ بررسی کنید که آیا یال‌های پیش‌بینی‌شده (مثلاً Coal→Oil→Autos) واقعاً با ترتیب زمانیِ سقوط واقعی صنایع در آن بحران هم‌خوانی دارد یا نه (با یک معیار کمّی مثل هم‌بستگیِ رتبه‌ای زمانِ اوج ضرر هر صنعت). (سطح دشواری: متوسط، بسیار مناسب برای یک مقاله‌ی «کاربردی/تجربی»)

### شکاف ۹ — عدم بررسیِ استحکام (Robustness) نسبت به انتخاب نُرم (Norm) و α

**شکاف:** فرضیات A به‌صورت ثابت α=۲ و نُرم اقلیدسی را انتخاب می‌کند. هیچ تحلیل حساسیتی نشان نمی‌دهد که آیا با α دیگر (مثلاً ۱ یا ۳) یا نُرم دیگر (مثلاً نُرم L∞ یا L1) نتیجه‌ی نهایی تغییر بزرگی می‌کند یا نه.
**سوال پژوهشی:** «چقدر گراف نهایی نسبت به انتخاب α و نُرم حساس است؟ آیا یک معیار داده‌محور برای انتخاب بهترین α (به‌جای همیشه α=۲ فرض‌کردن) وجود دارد؟»
**روش پیشنهادی:** تکرار کل تحلیل با چند α مختلف (با تبدیل حاشیه‌ای متناظر) و چند نُرم، و مقایسه‌ی گراف‌های نهایی با nSHD. (سطح دشواری: آسان تا متوسط)

### شکاف ۱۰ — جزئیات دقیق تخمین‌گرِ σ̂² برای max-projection ها به‌طور کامل در همین مقاله بیان نشده

**شکاف:** همان‌طور که در بخش A.۵ همین فایل اشاره کردم، مقاله می‌گوید «برای σ̂²_Mij از نمایشِ زاویه‌ایِ زیربردار (Xi,Xj) استفاده می‌کنیم»، ولی جزئیات دقیق (این‌که آیا k مخصوص هر زیرمجموعه انتخاب می‌شود، یا از همان k سراسری استفاده می‌شود؛ ثابت d′ دقیقاً چطور محاسبه می‌شود برای زیرمجموعه‌های بزرگ‌تر از ۲ گره) را به مقالات دیگر (Krali 2025 پیوست C.3، و Klüppelberg & Krali 2021 بخش 7.1.2) ارجاع می‌دهد — یعنی خودِ این مقاله به‌تنهایی **قابل بازتولید کامل نیست** بدون خواندن دو مرجع دیگر.
**سوال پژوهشی:** «آیا تخمین‌گر ساده‌شده (استفاده از یک R و k مشترک برای همه‌ی max-projection ها، مثل پیاده‌سازی بخش A همین فایل) از نظر خطای میانگین مربعات (MSE) بدتر یا بهتر از تخمین‌گرِ اصلیِ مقاله (با R و k مخصوص هر زیرمجموعه) عمل می‌کند؟»
**روش پیشنهادی:** پیاده‌سازیِ هر دو نسخه (که من نسخه‌ی ساده را همین الان برایتان پیاده و تست کردم) روی داده‌ی شبیه‌سازی‌شده با ground truth مشخص، و مقایسه‌ی مستقیمِ خطای تخمینِ A بین دو روش. این دقیقاً یک شکاف **«بازتولیدپذیری»** (ردیف ۸ چک‌لیست) است که به‌طور مستقیم قابل تحقیق است، چون شما همین حالا کد پایه‌اش را دارید! (سطح دشواری: آسان — بهترین گزینه برای اولین پروژه‌ی شما)

### شکاف ۱۱ — مقیاس‌پذیریِ محاسباتی برای d بزرگ‌تر از ۳۰

**شکاف:** الگوریتم ۱ (همان‌طور که در کد بخش A دیدید) دارای پیچیدگیِ تقریبیِ O(d³) در هر تکرار (برای هر j، برای هر i، محاسبه‌ی چند max-projection) است. برای d=۳۰ این قابل‌مدیریت است، اما مقاله هیچ بحثی درباره‌ی این‌که این روش برای شبکه‌های خیلی بزرگ‌تر (مثلاً d=۵۰۰ سهام در S&P500) چطور مقیاس پیدا می‌کند، ندارد.
**سوال پژوهشی:** «زمان اجرای الگوریتم ۱ و ۲ برحسب d چگونه رشد می‌کند (تجربی)؟ آیا می‌توان با موازی‌سازی یا روش‌های تقریبی (مثل محدودکردن جست‌وجو فقط به همسایه‌های نزدیک در یک گراف اولیه‌ی همبستگی) سرعت الگوریتم را برای d بزرگ افزایش داد؟»
**روش پیشنهادی:** بنچمارک‌گیریِ زمان اجرا برای d∈{10,20,30,50,100} روی داده‌ی شبیه‌سازی‌شده (دقیقاً با کد بخش A) و رسم نمودار مقیاس‌پذیری؛ سپس آزمایش یک نسخه‌ی موازی‌شده (با multiprocessing). (سطح دشواری: آسان تا متوسط — کاملاً عملی و بلافاصله قابل‌اجرا با کدی که همین الان دارید)

### شکاف ۱۲ — گسسته‌بودنِ اجباریِ اندازه‌ی زاویه‌ای به‌عنوان یک محدودیت مدل، نه فقط یک ابزار

**شکاف:** طبق فرمول (۵)، مدل RMLM اجباراً یک اندازه‌ی زاویه‌ایِ **گسسته** (با دقیقاً d اتم) تولید می‌کند. اما آیا وابستگیِ حدیِ واقعیِ بین صنایع اقتصادی واقعاً گسسته است؟ شاید وابستگی واقعی «نرم‌تر» و پیوسته‌تر باشد (مثلاً یک مدل کاپولای t-چندمتغیره با دُمِ سنگین، که اندازه‌ی زاویه‌ایِ پیوسته دارد).
**سوال پژوهشی:** «آیا می‌توان یک آزمون آماریِ رسمیِ نیکویی برازش (goodness-of-fit) طراحی کرد که بررسی کند آیا اندازه‌ی زاویه‌ایِ داده‌ی واقعی واقعاً به یک اندازه‌ی گسسته با d اتم نزدیک است یا یک ساختار پیوسته‌تر را ترجیح می‌دهد؟»
**روش پیشنهادی:** مقایسه‌ی برازشِ RMLM با یک مدل جایگزینِ پیوسته (مثل مدل‌های لجستیکِ چندمتغیره‌ی حدی یا کاپولای t) روی همین داده، با معیارهایی مثل AIC/BIC حدی یا آزمون‌های نیکویی‌برازشِ اختصاصی EVT. (سطح دشواری: سخت — نیازمند دانش عمیق EVT)

### شکاف ۱۳ — نبود روشی برای تفسیر «قدرتِ اقتصادیِ» یال‌ها (فقط وجود/عدم‌وجود یال گزارش می‌شود)

**شکاف:** گراف نهایی (شکل ۴) فقط یال‌ها را نشان می‌دهد (باینری: یال هست یا نیست)، اما وزن دقیقِ هر یال (â_ij) در تفسیر اقتصادیِ بخش ۷.۲ اصلاً استفاده نمی‌شود — یعنی معلوم نیست کدام یال‌ها «قوی» و کدام «ضعیف» هستند (فقط شکل ۵ به‌طور غیرمستقیم با تعداد تکرار در ۵ تخمین این را نشان می‌دهد).
**سوال پژوهشی:** «اگر یال‌های گراف را با ضخامتِ متناسب با â_ij رسم کنیم، آیا رتبه‌بندیِ صنایعِ "خطرناک‌ترین منبع سرایت" با آنچه در ادبیاتِ ریسکِ سیستمیک (مثل معیار CoVaR یا SRISK) شناخته‌شده، هم‌خوانی دارد؟»
**روش پیشنهادی:** محاسبه‌ی معیارهای مرکزیتِ وزن‌دارِ گراف (مثل out-degree وزن‌دار با â_ij) برای هر صنعت، و مقایسه‌ی رتبه‌بندیِ حاصل با رتبه‌بندیِ شناخته‌شده‌ی صنایعِ «دارای اهمیت سیستمی» در ادبیات مالی. (سطح دشواری: آسان تا متوسط)

### شکاف ۱۴ — نبود کد رسمی/بازتولیدپذیریِ کامل در زمان انتشار مقاله

**شکاف:** همان‌طور که در بخش A.۲ گفتم، مقاله می‌گوید بسته‌ی R «به‌زودی» در دسترس خواهد بود — یعنی در لحظه‌ی انتشار مقاله، **هیچ کدی برای بازتولیدِ دقیقِ نتایج در دسترس نبوده**. این یک شکاف در **شفافیت علمی (بازتولیدپذیری)** است.
**سوال پژوهشی:** «آیا نتایج گزارش‌شده در جدول‌ها و شکل‌های مقاله (مثلاً همان ترتیب علّیِ دقیق ۳۰ صنعت) با یک پیاده‌سازیِ مستقل (مثل همان چیزی که در بخش A همین فایل ساختیم) قابل بازتولید است؟»
**روش پیشنهادی:** این دقیقاً همان کاری است که خودتان با کد بخش A شروع کرده‌اید! نتیجه‌ی نهاییِ پیاده‌سازیِ شما را با فهرستِ ترتیبِ ۳۰‌تاییِ گزارش‌شده در بخش ۷.۱ مقاله مقایسه کنید — اگر یکسان یا خیلی نزدیک بود، یعنی بازتولیدپذیرید؛ اگر نه، دقیقاً مشخص کنید کجای پیاده‌سازی با توضیحات مقاله فرق دارد (این خودش یک یادداشتِ فنیِ ارزشمند برای انتشار است، حتی اگر کوتاه). (سطح دشواری: آسان — این طبیعی‌ترین قدم بعدیِ شماست)
